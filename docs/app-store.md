# Почему магазинная сборка умеет меньше

`Scripts/bundle-appstore.sh` собирает вариант, который принципиально можно
отправить в Mac App Store. Он умеет меньше обычного, и это не недоделка.
Здесь записано, что именно проверялось, чтобы к этому вопросу не возвращаться
каждые полгода.

## Что теряется

Медиа-вкладка видит **только Apple Music и Spotify**. Вкладка браузера с
ютубом, SoundCloud, VLC, подкаст — ничего этого в магазинной сборке нет.

## Почему нельзя оставить как есть

Обычная сборка читает MediaRemote — приватный фреймворк, который знает про
любой источник звука в системе. Дотягивается она до него через хелпер,
живущий внутри `/usr/bin/perl`: с macOS 15.4 демон отвечает только доверенным
клиентам, а перл — платформенный бинарь, которому доверяют.

В магазине это закрыто трижды, и хватило бы любого одного:

- **Приватный API.** Guideline 2.5.1. Отбраковывает автомат, читая бинарь, ещё
  до живого ревьюера. Поэтому маршрут вырезается на компиляции (`-DAPP_STORE`),
  а не гасится флагом в рантайме: строк не должно быть в файле.
- **Песочница.** Запуск постороннего исполняемого файла из неё невозможен:
  подпроцесс наследует песочницу родителя, а `DYLD_*` игнорируется для
  приложений из `/Applications` и под hardened runtime.
- **Лишний Mach-O в `Resources/`** — нарушение упаковки само по себе.

## Что проверялось и не сработало

| способ | почему нет |
|---|---|
| MediaRemote напрямую | приватный фреймворк |
| Хелпер в `/usr/bin/perl` | песочница + приватный фреймворк |
| То же через JXA / `osascript` | тот же фреймворк, тот же запрет |
| Попросить у Apple `com.apple.mediaremote.external-access` | стороннему разработчику профиль, авторизующий приватный энтайтлмент, не выдаётся в принципе |
| Accessibility, читать Control Center | песочница не даёт `AXUIElement`; штатного энтайтлмента нет |
| AppleScript к Safari и Chrome | нужна скрытая галка «Allow JavaScript from Apple Events»; Firefox не скриптуется вообще |
| Расширение для браузера + локальный сокет | работает, но это отдельный продукт и сеть, которую SECURITY.md обещает не трогать |
| Core Audio process tap | публичный API, но отдаёт звук без метаданных |
| Shortcuts / App Intents | такого действия нет |

Публичного API для чтения системного Now Playing на macOS не существует. В
macOS 26 его тоже не добавили.

## Чем это расходится с обещаниями проекта

Два места, и оба стоит держать в голове, а не обнаруживать заново.

**«Разрешений нет».** Маршрут через AppleScript просит «Автоматизацию» —
ровно то разрешение, от которого проект отказался в #23, выбрав per-client
MediaRemote. Магазинная сборка обещание нарушает, потому что другого пути в
магазине нет.

**Медиа-клавиши.** `PlayerBridge.postMediaKey` шлёт HID-события и требует
«Универсального доступа». Из этой сборки он вырезан: в песочнице не работает и
правилам противоречит. Значит, когда не играет ничего скриптуемого, кнопки
управления не делают ничего — им некому адресовать команду.

## Как выглядит рынок

Никто из тех, кто показывает произвольный плеер, в магазине не живёт: Seam,
NotchNook, Boring Notch раздаются с сайта. Те, кто в магазине — Perch,
LookieLoo, Notchy — умеют Apple Music и Spotify, и только их.

## Что ещё не сделано

Сборка собирается, подписывается и запускается под песочницей, но до отправки
не доведена. Осталось:

- **Полка.** `ShelfStore` хранит голые пути в `UserDefaults`. В песочнице
  доступ к брошенному файлу живёт один сеанс — после перезапуска полка
  опустеет. Нужны security-scoped bookmarks; энтайтлмент под них уже выдан.
- **Сертификаты.** Нужны Apple Distribution и 3rd Party Mac Developer
  Installer, provisioning profile и запись приложения в App Store Connect.
  Сейчас скрипт подписывает ad-hoc — этого хватает только чтобы запустить.
- **Упаковка.** Отправляется `.pkg`, собранный `productbuild` и подписанный
  installer-сертификатом, а не `.app`.
- **Тексты разрешений.** В `Info.plist` они только по-русски при
  `CFBundleDevelopmentRegion = en`. Место им в `InfoPlist.strings` по локалям.
